# `crates/bd-server`

The file-by-file guide to this crate, kept apart from the root `AGENTS.md` so it loads only when working here. Update it when a change affects what it says. The root `AGENTS.md` applies here too, its Conventions & Patterns above all.

- `crates/bd-server` (library `bd-server`: `bd serve`, over `bd-cli`'s commands): `serve/` (`bd serve`; `bd serve check` (`serve/check.rs`) reads `auth.toml` as the server would (the root canonicalized once; running its `[secrets]` command on Unix only as the root's owner (`gate`): anyone else, root included, is denied every command (`helper::forbid`) before anything loads, and exits 2 when `auth.toml` has `[secrets]`) and prints what to register; at most `MAX_CONNECTIONS_PER_PEER` connections per non-loopback address (`PeerSlot`); text logs escape every control character in fields (`logging::Escaped`), as request values are logged, and panics are logged entries (`logging::log_panics`); each connection's address rides on its requests (`Peer`), on request lines and on `request refused` lines (`log_refused`, for unknown, expired and forbidden tokens); `authorize`, `open_app` and `close_app` are shared with `ToolRunner`, which runs `/w/<name>/mcp` tool calls as `<token actor>/mcp` (or `?session=<name>`) without the token's admin and human rights; and `operation_approval` for `<public url>/w/<name>/(close|discard)/<id>?request=` (`routes.rs`'s `op_path`, after `gate_path`), the same 404s and POST checks, every POST answer recorded (cross-site, unreadable body, busy, join error; a settings failure only when its `approval` id names a live approval for that path, `authorize::pending_operation`, peeked, not taken), and `impl authorize::Operations for Server`: `find` (Done for a closed close target, Changed for a pinned or gate target or a discard target no longer a run, a closed run still discardable, NotHeld without `gates_in_the_way`, else the gates with `may_open` for the approver and the deletes capped at 50) and `perform` (one `Store::write` under the approver's human, non-admin `Policy`, the target checked again, then `close_issue`/`discard_run` with the sealed reason and flags, `take_over` false, `via` browser and `requested_by`;
