# `crates/bd-core`

The file-by-file guide to this crate, kept apart from the root `AGENTS.md` so it loads only when working here. Update it when a change affects what it says. The root `AGENTS.md` applies here too, its Conventions & Patterns above all.

- `crates/bd-core` (library): `store.rs` (WAL pragmas, busy handler, `Store::write` = one `BEGIN IMMEDIATE` transaction with a `WriteCtx`), `schema.rs` (migrations via `PRAGMA user_version`), `error.rs` (`Error`; `Error::Approvable` wraps a refusal a person could approve in the browser, its text, code, exit code, `needs` and `gate` those of the inner error: `approvable()`, `is_approvable()`, `unmarked()`/`into_unmarked()` for matchers), `issues.rs` (lifecycle; `CloseOptions.requested_by`, and `DeleteOptions`' `reason`, `via` and `requested_by`, written to the `closed`/`deleted` events when set, a blank reason dropped and any other kept byte for byte), `graph.rs` (typed edges, cycle/hierarchy checks, materialized `is_blocked`), `ready.rs`, `claims.rs` (leases, fencing tokens, reclaim), `events.rs`, `comments.rs`, `memory.rs`, `transfer.rs` (JSONL, beads-compatible import), `asof.rs` (`bd show --as-of`: an issue rebuilt from its retained events by a forward and a backward pass, reporting unknown what they cannot agree on, never guessing; `History`, the context loaded once per command (head, floor, purges), and a per-issue `Loaded` that `rebuild` replays at many points; `issue_as_of` wraps them), `compaction.rs` (`bd compact`: candidates, stats, and `WriteCtx::compact_issue` replacing a closed issue's text with a summary, the original kept in the `compacted` event), `specs.rs` (the experimental feature specs: the spec tree over a `Source` (`spec_views`, `ancestors`, `render`, ported from the former `spec.mjs`), the issues linked to specs, `drift` since `experimental.specs.since` (and `unlinked_counts`, `bd prime`'s counts, through the same scan as drift's), `candidates`, `list`; `config::set` records the since key when specs turn on; `specs/history.rs`, read-only: `bd spec show --as-of`, the same `spec_views`/`render` over an `AsOfSource` of issues rebuilt at the point by asof's `History` (a shared `Rebuilder` loading each issue once, capped at `MAX_HISTORY_ISSUES` issues charged and `MAX_HISTORY_REPLAY` events replayed; ids only a later purge, compaction or import names (`After::hidden`) are probed uncharged and count only when their history ties them to the specs asked about), what the history cannot tell in the views' `unknown`, never guessed; `bd spec changes`, over the events after `--since` read once (a rowid range for a seq, `idx_events_ts` for a time), each candidate (`raw_candidates`: current parent-child edges, edges and delete and update-import snapshots in the window, purged ids, unfiltered by membership) classified at `--since` and after each of its window transactions that could change it (`inert` ones are not rebuilt); `parse_bound`, `render_changes`; tests in `specs/history/tests.rs`), `spec_edit.rs` (`bd spec new/add/change/remove/link`: validation and the writes over `create_issue`, `add_dependency`, `close_as` and `close_issue`, no SQL), `spec_context.rs` (the specs governing an issue for `bd show`/`bd claim` and whether a link covers it for `bd close`'s hint: a walk of its lineage, ancestors and descendants breadth-first, bounded at 500 descendants and 5000 related edges), `duplicates.rs` (`bd duplicate`/`bd supersede`: an informational edge and the close in one transaction; `similar_pairs`, the pure search behind `bd find-duplicates`), `metrics.rs`, `doctor.rs`, `queries.rs` (read API trait), `query/` (`bd query`'s expression language: `lex.rs` and `parse.rs` parse to a positioned AST (`Expr`, each comparison with its value's column) with limits (`MAX_BYTES` 4096, `MAX_COMPARISONS` 128, `MAX_DEPTH` 32 counting every NOT and every parenthesis, checked at the token that crosses it) that keep the compiled SQL far under SQLite's expression depth; `mod.rs` holds the canonical `Display` (only the parentheses the grouping needs) and `query_error` (column and caret, exit 2); `compile.rs` compiles to one parameterized, two-valued condition over `issues i` (values always bound, LIKE through `like_escape`, `parent` values through `issues::lookup_id`); `tests.rs` holds the seeded fuzz, round-trip and at-limit tests), `hierarchy.rs` (epic status counted over the subtree, close-eligible epics (shared with `bd stats`), child issues, stale work and expired leases, orphan text references through rename's `id_tokens`), `subgraph.rs` (the bounded walk up and down from an issue, or the open issues, for `bd graph`), `gates.rs` (gate conditions in `metadata.gate`, arming via `graph::recompute`, local evaluation, escalation; `GateRepos`, also `github.repos`; a human gate's `GateSpec.approvers`, read apart from its condition by `approvers_in` (a stored list that is not valid reads as `Some([])`, matching nobody, and never breaks the condition), new input through `approvers_input`/`check_approvers`, set or cleared on the raw metadata by `WriteCtx::set_gate_approvers`; `run_of`; `approval_id_ok`, the ids an approval link may name, shared with bd-server's gate page; `GateView` and `GatePhase` deserialize, for `bd gate review`'s remote reads), `github.rs` (`bd github`'s pure engine: GitHub issues and comments, per-side `Fields` hashes, field-wise pull changes and push bodies, issue and comment markers, decisions (`Deferred`, `newer`'s edit times), comment plans with adoption, and `WriteCtx::github_apply`/`github_create`, the per-issue apply with the pull part in a nested savepoint), `requests.rs` (idempotency records: a request id stored in the same transaction as its write), `policy.rs` (claim ownership for every caller: ending or taking over another actor's live claim needs the operation's `take_over`, never its `force`, and is recorded as `claim_override` in its event; and what a `bd serve` request may override, set per transaction with `WriteCtx::set_policy`: other actors' claims need an admin token, human gates a human one (of one of the gate's approvers when it names them: the per-gate `shut` predicate, `may_open`, which the hold walks use on every human-gate path; `may_edit_approvers` for changing a list, a human approver's or a human admin's; refusals through `gate_refusal`, `human_only` for non-human tokens, naming the gate a person must open: `Error::Needs.gate`, set by `Error::with_gate`, read by `Error::gate()`, which `render_error` and MCP tool errors print as `gate` and, with an approval link, `approval_url`; `gates_in_the_way`, every open human gate a close or removal of some ids gets past (the issue itself, gates on its and its live ancestors' `blocks` edges, gates below it and on its live descendants' edges), read only on the refusal path, so `check_close`'s forced branch (never for a gate target) and `check_removal_gates` mark a refusal `Error::Approvable` only when every such gate has a valid approver list); and a token's `max_claims`, the issues its actor and sub-actors may hold, checked once per write transaction before it commits), `lockfile.rs` (OS file locks over files outside the database, `File::try_lock` waiting up to the busy timeout, then `Error::Locked`: a checkout's `.bd/agents.lock.mutex`, a workspace's `.bd/publish.lock`), `publish.rs` (`bd publish`: a versioned `PublishBundle` (playbook texts by path; each harness's set as raw files and in-set symlinks; client-reported git commit and dirty flag; caps checked while parsing), `check_path` and symlink rules before any write, `read_tree` of a source directory (the client's, or `publish.prev` for `--rollback`), `prepare` = under the publish lock, sweep old staging, stage into a private `.publish-<random>`, validate with `AgentSet::load` and a contained playbook `Loader`, compare (`AreaPlan`); `Prepared::apply` = copy the areas to `publish.prev`, write each new or changed file by temp and rename (never through a symlink), removals last; `Prepared::record` = one `published` event plus the agents revisions (`agents::record_in`) in the caller's transaction; tests in `publish/tests.rs`), `playbook/` (playbook files: strict parsing, `{{var}}` templates and conditions, `extends`/`expand` loading (`Loader::contained`: every file read inside the search directories and within `MAX_BUNDLE_FILE_BYTES`, used for bd serve's own playbooks and publish validation), bundles of a remote client's playbook files that the server loads without touching its disk, compile to a size-limited `Plan`, runs (`run_issues`: a run and every issue below it, what `discard_run` deletes; `DiscardOptions`' `reason`, `via`, `requested_by` passed to its `DeleteOptions`), extract), `agents/` (agent assets, one set per harness in `.bd/agents/<harness>/`: `mod.rs` (`Harness`, its client destinations, limits), `set.rs` (strict `AgentSet::load` with symlinks contained in `.bd/agents`, manifests and revisions; `check` re-validates what a client receives), `mcp.rs` (MCP definitions: strict parsing, field-name rules, canonical JSON hashes), `changes.rs` (revisions recorded in the meta table, `agents_changed` events; `record_all` also records the playbooks' revision, its event naming `"area": "playbooks"` instead of a harness), `playbooks.rs` (`PlaybookSet`: the workspace's `.bd/playbooks/**` served for client approval, read as strictly as a set within the bundle limits, manifest and revision, `check` for what a client receives)).
