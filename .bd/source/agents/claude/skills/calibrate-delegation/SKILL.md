name: calibrate-delegation
description: Gather the evidence for changing the delegation rules (model and effort per task in AGENTS.md) or the rubric's complexity anchors. Use before changing either, or when asked how agent runs compare on cost, time, score or reviewer catch rate.
---

Change the delegation rules in AGENTS.md ("Delegating to agents"), or the complexity anchors in `.bd/rubric.md`, only from evidence. The `recalibrate` playbook (`.bd/source/playbooks/recalibrate.toml`) does this every 10 confirmed scores behind a human gate; use this skill to answer a question in between or to prepare a proposal.

- `node .github/scripts/calibrate.mjs` reports every `change` run's estimate against judged complexity, its score and findings, and its cost and agent time by role, model and effort (Copilot AI credits as USD; Claude Code tokens at the notional list prices in `.github/scripts/prices.json`), with time by step and cost and time by complexity band; agent time is the primary figure, elapsed time and human wait at gates are context, reported apart. Roles come from workflow agent labels and, for plain subagents, the role prefix AGENTS.md asks every Agent-tool description to start with (`coder:`, `reviewer:`, `mechanical:`, `research:`, `planner:`, `summary:`), else a description naming a review; anything else is other. Its Score by coder section sets each scored run's coder (the model and effort with the most requests among its workflow coder agents, or among its `coder:` subagents when it has none) against mean overall and serious findings by complexity band, and counts the runs carrying the coder exploration quota's `exploration` metadata, which `--json` also shows on each run.
- `node .github/scripts/reviewer-catch.mjs` reports, by complexity band, how often each reviewer model and effort catches what a paired pass on the same diff and prompt found: from the Copilot CLI extension's `files/workflow-agents/` journals, the Claude Code workflow's journals on this machine, and review passes run as plain `reviewer:` subagents paired with a shadow by identical prompt (findings read from prose, so lossy). The header counts pairs and unknown bands per source. It flags thin cells (under 5 pairs).
- Every `change` run requires a shadow review (the Copilot extension's default shadows, or `shadowReview: { model, effort }` on the Claude Code workflow), so the data grows with each run; point the shadow at a thin cell to fill it.

Both reports split their complexity tables by rubric version (`.bd/rubric.md` Version; calibrate counts a run under its judged score's version and counts estimate/judged pairs of different versions apart as mixed), so compare like with like: base a rule or anchor change on runs judged under one version.

Current evidence behind the gating-review rule in AGENTS.md (strongest class; medium effort at complexity 3 or below, high at 4-5) is borrowed from the sibling squid project's `reviewer-catch.mjs` as of 2026-10-17, paired passes on one diff and prompt: `sonnet`/medium caught 47%, 48%, 55% and 40% at bands 2-5 against `opus`'s 66%, 61%, 56% and 73% (`opus`/medium at bands 2-3, `opus`/high at 4-5; 24, 37, 18 and 14 pairs), and of validated findings at band 5 `opus` raised 4 to `sonnet`'s 0; the effort split rests on where serious findings concentrate (63 of 72 at bands 4-5), not on effort pairs. It is provisional here until bd-sync's own pairs fill the cells. Update this paragraph when the rule changes.
